1. While you’re in a gdb session, how do you set the arguments that will be passed to the program when it’s run?
`set args arg1 arg2 ...` (or start gdb with `gdb --args ./prog arg1 arg2`).

2. How do you create a breakpoint?
`break <line>` or `break <function>` (abbrev: `b`). E.g. `break main`, `break foo.c:42`.

3. How do you execute the next line of C code in the program after stopping at a breakpoint?
`next` (abbrev: `n`) — steps over, executing the whole function call in one go.

4. If the next line of code is a function call, you’ll execute the whole function call at once if you use your answer to #3. How do you tell GDB that you want to debug the code inside the function (i.e. step into the function) instead?
`step` (abbrev: `s`) — steps into the function.

5. How do you continue the program after stopping at a breakpoint?
`continue` (abbrev: `c`).

6. How can you print the value of a variable (or even an expression like 1+2) in gdb?
`print <expr>` (abbrev: `p`). E.g. `p x`, `p 1+2`, `p/x x` for hex.

7. How do you configure gdb so it displays the value of a variable after every step?
`display <var>` — prints it automatically after every step/continue. Undo with `undisplay <n>`.

8. How do you show a list of all variables and their values in the current function?
`info locals` (use `info args` for parameters, or `info scope <func>` for both).

9. How do you quit out of gdb?
`quit` (abbrev: `q`).
